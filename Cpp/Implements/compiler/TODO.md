- [ ] Add a REPL — a loop that reads a line, parses it, and evaluates it, keeping top-level state across inputs. Roughly 100 lines on top of what you have, and it makes the interpreter feel like a real language to use. It's also how you'll discover UX bugs nobody writes tests for.
- [ ] Write a bytecode VM — compile the AST to a stack-machine instruction set (roughly 30 opcodes: LOAD_LOCAL, STORE_LOCAL, PUSH_INT, ADD, CALL, RETURN, JUMP, …), then execute that. This is where inferred_type becomes genuinely useful, because the compiler can pick ADD_I64 vs ADD_F64 per instruction. The checker is already the right place to do any extra work.
